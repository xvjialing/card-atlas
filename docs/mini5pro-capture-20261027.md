# Mini 5 Pro 成功快传抓包分析

## 结论

后续普通重连与实际下载的复核见 [重连分析](mini5pro-reconnect-20261027.md)。其中更正了51/17与能力消息字段的解释，实机成功状态以最新验证记录为准。

本次抓包足以定位 CardAtlas 的协议适配差异。Mini 5 Pro 接受的 `0x51/0x02` 开启载荷是 11 字节，原代码使用旧机型的 5 字节载荷；随后双向身份确认、能力协商、素材广播路由和目录解析也有不一致。之前的 macOS EPIPE 是另一层问题，不解释握手已完成后的素材会话失败。

已依据捕获修正这些布局，并使用脱敏报文和真实结构目录进行离线模拟验证。没有使用原抓包的设备序列号、手机安装身份或固定 WLM 地址作为运行时身份；没有重放飞控初始化、激活、时钟或国家码设置。修正版尚未完成实机连接和原片下载验收。

- 原文件：用户提供的 `PCAPdroid_27_10月_08_18_35.pcap`，约 67 MB。
- SHA-256：`e82522ec0b71170fc7d6cea5d9d56ca7be86a03e40b80ea8424e0abce7df7f24`。
- 时间：2026-10-27 08:18:45.883–08:19:58.877，Asia/Shanghai，共约 73 秒。
- 共 18,626 个 IPv4 包，未发现抓取截断；其中 4,871 个包与无人机 `192.168.2.1` 通信，4,527 个是 UDP 9003。
- 文件封装为 Raw IP，**没有蓝牙 HCI/GATT 数据**。虽然录制从长按授权前开始，不能据此逐字节核验蓝牙授权；本次可直接核验的是之后的 Wi-Fi 会话、目录及缩略图读取。
- PCAPdroid 非 root 抓包会代理 L3/L4。记录中的客户端端口 58204 不足以证明 DJI Fly 原始 socket 使用哪个本地端口，不能仅凭它把客户端 9003 绑定改成临时端口。

## 目录布局

首批存储卡目录的头部记录数为45，第二字段为23318，但完整线上目录仅12326字节；机身首批也是45/23318，线上12339字节。捕获中第二字段恒为 `8 + 518 × 记录数`，它不是线上实际总字节数。

每条记录有18字节固定头。`+17` 是短扩展长度；`+18` 的 `19 06 00 00 00` 后，`+23` 是完整的16位扩展长度。完整记录长度为 `18 + 扩展长度`，短值为完整长度与255的较小者。视频的扩展可超过255字节。

完整性现在由 DUML CRC、分片序号及末片标记、记录数、每条扩展边界和尾部完全消费共同判断。原始名称、原片路径、缩略图路径均从记录中读取，不再根据 DCF 编号猜文件名。

捕获中的目录并不等于整个资料库总量：首批两种存储各45条，后续还有分页、连拍成员查询等。回归样本包括45条存储卡、45条机身存储、57条连拍和1条全景记录。

## HTTP 与缩略图

共看到54个无人机 HTTP 请求，均使用 `storage=1`，对应本次用户浏览的机身存储：45个 `.thm` 请求、7个 `.mp4` Range 请求、2个 `.dng` Range 请求。已完整观察到53个成功响应（44个200、9个206），响应正文开头均为 JPEG；另一个请求的响应未在文件内完整出现。

例如 #13622 对视频请求 `bytes=507122943-507138681`。对应记录的 `0x1d` 描述中，`+0 u32` 为15739字节，`+8 u64` 为507122943，恰好对应此范围。两份 DNG 的缩略图从101888字节开始，长度也与描述一致。客户端现在限制缩略图读取不超过4MiB，拒绝忽略 Range 或返回错位范围的服务响应。
