# 设备素材导入

## 产品与摄影工作流

CardAtlas 分为“设备导入”和“素材分析”两个入口。前者把摄影设备原片带回电脑，后者分析存储卡、已挂载磁盘或本地素材。设备品牌不决定归档与任务模型。业务依据是本次用户要求：通用设备素材导入，先整合 osmo-bridge 的 Action 6 连接和导入，兼顾产品流程和摄影使用。

当前无线适配覆盖 macOS 上的三款设备：DJI Osmo Action 6（蓝牙配对 + 热点，待实机验证）、DJI Mini 5 Pro（蓝牙电源键授权 + 热点，实验接入：已按成功抓包适配存储卡与机身存储，待实机复测）、Sony ZV-E10（二维码照片导入 + 热点直连，按能力使用 UPnP 或 PTP/IP；固件 2.01 已验收相册、RAW 缩略图与视频播放，导入待实测）。其他品牌的已挂载存储仍可通过素材分析使用。

1. **连接设备**：Action 6 走蓝牙发现与配对 → 相机屏幕确认 → 扫描并选择真实热点；Mini 5 Pro 先蓝牙搜索无人机，配对时在机身长按电源键约 3 秒完成授权（与 DJI Fly 手机快传首次连接一致），随后扫描选择热点；ZV-E10 在回放界面进入“发送到智能手机”并选择素材，可把该界面显示的二维码拍成照片导入，再扫描选择设备热点。选定热点并明确确认后才切换 Wi-Fi，也可先通过系统 Wi-Fi 菜单加入热点再接续。
2. **挑选原片**：真实缩略图、照片/视频预览、拍摄日期、存储位置和时长；按类型、日期闭区间、存储、文件名筛选。默认网格，也可切换列表或按拍摄日分组的时间线。三种视图每页 30 项，共用选择；时间线“全选当天”覆盖当前筛选条件下所有分页，并显示半选状态。类型与存储筛选直接展示为按钮组，提示筛选外的已选素材。
3. **确认归档**：先选择目标文件夹，查看数量、目标和路径示例，再开始导入。保留所选资源的字节和拍摄时间，客户端不转码、不删除设备文件。Sony 提供的资源可能已由相机转换或缩小，不能把它一概认定为卡上原片；例如 RAW 标题对应 JPEG 资源时以 `.JPG` 保存，并在导入完成后提示转换版本。
4. **检查结果**：提交后自动弹出任务窗口，区分下载、生成本地指纹、最终保存、完成；支持暂停全部、恢复当前设备的未完成任务、单项重试、定位文件，并打开导入目录继续素材分析。关闭窗口后后台继续，顶部“导入任务”可重开。记录不再堆在页面底部；弹窗区分本次导入与全部记录，使用后端规划的 taskIds 确保历史任务不影响本次进度。

| 策略 | 目录 | 用途 |
| --- | --- | --- |
| 按拍摄日期归档（默认） | `photo/YYYY/MM/DD/原文件名`、`video/YYYY/MM/DD/原文件名` | 与现有资料库一致 |
| 保留设备原目录 | `设备原目录/设备标识摘要/存储标识/原路径` | 保留机内层级，区分机身和存储介质 |

没有有效日期时放入 `日期未知`，不会拿导入当天冒充拍摄日期。Action 6 清单时间不带时区，按本机时区解释；EXIF 与视频内部元数据保持原样。清单容量可能受 32 位协议字段影响，界面显示估计值，下载以 HTTP 实际长度为准。

重名文件追加 `_001` 等编号，不覆盖已有文件。重复导入判断只适用于适配器、设备、素材身份、日期、长度、目标目录和目录策略一致的已有记录，不按文件名做内容去重。已有完成记录的目标文件丢失或长度变化时可以重新导入；同长度内容变化不能只凭记录识别。

## 扩展架构

```text
DeviceImportPage / DeviceConnectionDialog
  ↓ Wails 类型绑定
DeviceService：目录选择、文件定位、应用入口
  ↓
deviceimport.Manager：规划、重名编号、持久化、队列、恢复
  ↓ Provider 接口
devices/action6   devices/mini5pro   devices/zve10
  ↓                    ↓                  ↓
dji + dji/transfer  wifihost + dji    wifihost + upnpav
```

`internal/deviceimport/types.go` 定义接口。`Descriptor` 表达类型、连接方式、平台可用性、兼容性和可筛选存储来源；`Session` 表达连接阶段、会话令牌和清单版本；`Media` 使用字符串存储标识，不依赖 DJI 的整数编号；`Task` 固化设备、素材快照、目标及相对路径。

新增设备时实现 `Provider` 并注册到 `NewManager`。品牌参数和原始清单字段在适配器内解释，通用队列不增加品牌判断。热点类设备共享 `internal/devices/wifihost` 的会话状态机（扫描、确认加入、手动接续、钥匙串凭据、断开恢复原网络；可选蓝牙授权钩子 Prepare/Discover，配对成功后固化设备标识与热点提示）；素材协议留在适配器内：Mini 5 Pro 使用 `dji.AircraftLink` 的 UDP 9003 / WLM 会话，分别按存储卡与机身存储分页读取；蓝牙复用 DJI FFF0 传输并使用 `DJI FLY` 配对标识，会话失败时报告实际阶段并停止唤醒保活，ZV-E10 经 `internal/upnpav` 发现服务及读取传输能力，旧固件保留 ContentDirectory，PTP/IP 素材由 `zve10/ptp_media.go` 适配并接入受控传输器；下载仍通过 `transfer.DownloadURL` 复用续传、长度核对与发布机制。ZV-E10 的连接表单支持把相机显示的连接二维码拍照导入：`ConnectionRequest.Photo` 携带前端缩放后的照片数据，适配器解码并预填热点信息，仍然需要用户确认才会切换 Wi-Fi。二维码解析覆盖索尼 `W01:S:…;P:…;C:…` 配对格式（热点名按 `DIRECT-<S>:<C>` 重组，热点后缀片段匹配兜底）、Android `WIFI:` 格式与常见键值行。连接表单按设备呈现自己的入口（蓝牙、热点扫描、二维码），复用素材列表与任务界面。预览路由按 provider 分发到各适配器的受控处理器，前端只提交素材 ID 和会话令牌，不提交任意设备地址或路径。

首版只允许一个活动设备、串行下载。未虚构未来设备协议。通用队列测试使用名为 `future-camera` 的模拟适配器，验证品牌无关性。

## 数据与恢复

- 系统用户配置目录 `CardAtlas/devices/` 保存配对身份、导入记录和脱敏日志；`CARDATLAS_DEVICE_DATA` 仅供测试或独立配置使用。重启后未完成任务变为暂停，不自动切网或下载。
- 队列成功落盘后才开始下载。原记录损坏时阻止新导入，不覆盖原文件；保存失败保留界面告警。导入记录长期保留在本机、每页 10 项；本地分析导出记录仍为进程内最近 20 次。
- 密码提交后保存至 CardAtlas 独立的 macOS 钥匙串命名空间，不与 Osmo Bridge 混用。密码不进入状态、日志、URL、普通 JSON 或浏览器存储，可修改或忘记。
- 热点切换必须明确提交。Action 6 认证失败保留蓝牙会话，允许重试或手动加入；Mini 5 Pro 失败后立即释放蓝牙唤醒，等待选择热点超过 90 秒也释放，避免无限保活。只有主动取消、断开、退出才尝试恢复原网络，恢复失败明确提示。
- 续传核对设备、存储、路径、日期和清单长度；其他设备不能恢复旧任务。未通过蓝牙识别的手动会话不跨重连自动续传。
- `os.Root` 将目标操作限制在用户选择目录，拒绝危险名称、越界路径和非普通续传文件。发布目标不覆盖现有文件；不支持硬链接时采用独占创建、复制与读回哈希检查。
- 若发布文件后、队列落盘前断电，可能出现“文件已存在但任务未完成”。应用停止覆盖并保留错误，需要核对文件或更换目录重新选择，不擅自认定完整。
- 下载检查 HTTP 范围和长度，并生成本地 SHA-256 指纹。设备未提供源端哈希，不宣称源端哈希核验通过；预览不等于原片已保存。磁盘空间不足由实际写入报错，清单估计不能保证剩余空间足够。
- 二维码照片只在适配器内解码，读到的热点密码与手动输入同样保存到本机钥匙串。Sony 二维码目前仅预填配网信息，尚未建立可信设备持久身份，因此仍不跨重连自动续传。ZV-E10 的描述文档、控制地址和素材资源必须与发现报文来源同机；禁止 DNS 主机、凭据 URL、跨机引用与 HTTP 重定向。
- 无云上传、遥测、设备删除或格式化。保留迁入的日志脱敏、按天及容量滚动；客户端侧栏“诊断日志”提供历史查看、级别筛选、详细记录切换、打开日志目录和导出 ZIP 诊断包。

## 验证与后续

Go 测试覆盖通用规划、碰撞、恢复、持久化失败、固定协议报文、UDP 模拟设备、HTTP 续传和预览。热点会话状态机（wifihost）覆盖扫描分类、确认加入、凭据记忆、手动接续、断开恢复与链路中断；Mini 5 Pro 覆盖双存储分页、抓包会话布局、变长 DNG/视频目录和内嵌 JPEG 范围、危险路径跳过与受控预览校验；UPnP 层覆盖描述解析、SOAP 浏览与分页；ZV-E10 覆盖二维码解码往返、连接信息解析、UPnP 条目标准化与同机地址校验。浏览器脚本 `frontend/tests/device-browser-check.mjs` 导出检查函数，接受 Playwright page、工程根目录及 `device-fixture.mjs` 文本，通过模块请求拦截注入模拟接口；不打包测试数据，不执行真实导入。

实机仍需覆盖首次系统权限、相机屏幕配对、实际热点认证、内置存储与 SD 卡、大于 4 GiB 视频、断网重连、外接盘实测和网络恢复。Mini 5 Pro 的 DJI 传输协议与 ZV-E10 的 UPnP 媒体服务均以标准或既有实现为准，必须实机核对清单格式、缩略图与 Range 支持。未来按设备能力扩展 RAW+JPEG 关联选择、分段视频与伴随文件、双份备份、源端哈希；当前不作已支持承诺。

## Sony ZV-E10 固件 2.01 PTP/IP 真机调试（2026-10-31）

用户明确授权在当前工程直接真机调试。此次相机的实际返回推翻了此前仅按 SOAP/UPnP 实现素材服务的假设：`DmsDescPush.xml` 可读，控制地址也被发布，但实际 `X_TransferStart`、`GetSystemUpdateID`、三个目录入口的 `Browse` 均返回 HTTP 404；请求头大小写差异没有改变结果。

`DigitalImagingDesc.xml` 明确报告固件 `2.01`、`X_PTP_Versions=3.00`、`X_PTP_MediaServerSupport=Enable` 和无需配对。PTP/IP 15740 端口可达，实际 `GetDeviceInfo` 再次确认型号为 `ZV-E10`、厂家为 `Sony Corporation`。UPnP 描述使用的是 `SonyDigitalMediaServer / SonyImagingDevice` 通用名称，不能再要求这些字段必须出现 ZV-E10；通用名称仅结合用户已选一代热点及两项素材服务接受，PTP 路径再按真实型号严格校验。

| 客户端视频预览 | 通过：92.01 MB、7 秒 MP4 出现实际画面，播放进度达到 5 秒；会话保持连接 |

已选一代热点优先直连 PTP/IP，并以实际设备信息再次严格确认型号，避免旧描述服务未就绪时阻塞真实素材协议；不可达时仍保留同机 DigitalImaging 能力识别与旧 UPnP 路径。PTP/IP 使用固定版本 `alpha2go v0.3.0`（Apache-2.0），命令、事件双通道均使用相同 Wi-Fi 源地址及接口。优先保留原生发送模式；只有存储尚未开放时才按能力协商 Sony 素材模式；固件 2.01 的实机检查还确认需要在 Sony 握手后读取一次 0x9209 状态再开启素材模式，并等待异步发布。实机发现全量 MTP 批量属性请求会超时，因此使用逐对象读取，连接总等待限制调整为四分钟；标准日志记录进度及空存储等待，不记录文件名、原始协议载荷或设备唯一标识。

PTP 对象经会话内受控 HTTP 传输器接入既有预览与 `transfer.DownloadURL` 续传流程，不对外开放新监听端口。资源只能是当前会话已列出的对象句柄；支持单范围、后缀范围和 64 位偏移，优先用相机明确支持的 Sony 0x9211，每块最多 512 KiB。预览提前关闭只丢弃已读块，排队取消不关闭共享会话；断开时释放自行启用的素材模式。RAW 保留真实原文件与扩展名，预览仍使用相机 JPEG 缩略图。

模拟 PTP 相机回归覆盖协议初始化、机型拒绝、原生模式保留、素材模式释放、列表、逻辑目录、分段字节、提前关闭后的再次读取、排队取消、地址限制、范围边界和 64 位大小；UPnP 能力描述仍有同机校验。新增的 `sony_live_probe` 构建标签和 `CARDATLAS_SONY_LIVE=1` 必须同时显式开启才接真机；探测不切换 Wi-Fi、不读钥匙串、不导入、不删除或拍摄。`CARDATLAS_SONY_SSID` 只提供用户已选目标，用于 macOS 命令行无法读取 SSID 时的匹配上下文；网卡地址、实际请求与相机返回均来自真机。

最终在当前工程构建的原生客户端验收，源相机与文件均为真机，不使用浏览器模拟数据。本次 PTP 型号确认到完整清单约 130 秒；所有素材读取警告计数为 0。结束时已清除 JPEG 测试搜索、关闭预览弹窗并保留连接与全量列表，没有提交导入任务。该素材集合未找到 JPEG 文件，未单独验收 JPEG 原图预览；不据此扩展为其他固件、大于 4 GiB 或完整导入/续传已验证。

## Sony ZV-E10 DHCP 网段修复（2026-10-31）

本次实机截图显示 Wi-Fi 已连接且使用 DHCP：Mac 为 `192.168.0.5`，掩码 `255.255.0.0`（`/16`），路由器为 `192.168.122.1`。同日客户端日志显示热点认证成功，随后在地址预检阶段超时，尚未建立媒体会话。此前只接受 `10.0.0.0/24` 和 `192.168.122.0/24`，将有效的 `/16` 客户端地址误判为尚未获得地址。

Sony 改为从实际 Wi-Fi 网卡读取 IPv4 地址与掩码，确认该链路包含已知相机地址 `10.0.0.1` 或 `192.168.122.1`，并将实际网段用于 SSDP 来源校验。不会将整个 `192.168.*` 地址范围无条件视为就绪：旧网络 `192.168.5.47/24`、掩码不覆盖相机的 `192.168.0.5/24`、自分配地址、网络/广播地址与相机自身地址均拒绝。已知 SSID 不匹配时仍拒绝；DJI 的固定网段判定保留。描述、控制端点与素材 URL 的同机校验沿用原有规则。

地址错误提示区分“没有可用 IPv4”和“已有地址但地址或掩码不匹配”，后者显示实际地址及前缀；已使用 DHCP 时提示续租。成功预检后的日志记录 Wi-Fi 接口、客户端 IPv4 与实际发现网段，便于继续定位媒体发现阶段。

回归覆盖截图网络、原有两个 `/24` 网络、非整字节掩码的广播边界、无效地址、热点匹配及 DHCP 由旧地址变为 `/16` 的等待过程。相册浏览、预览与续传仍使用离线相机模拟器验证；本次修复不代表已完成相机实机相册验收。

### 素材发现与一代菜单区分（同日后续）

重试日志已显示 `wifi.address_ready`（`en1`、`192.168.0.5/16`），随后在 SSDP 等待约 3 秒后返回素材发现失败。此前发现代码没有记录响应数量、描述读取失败或机型拒绝原因，因此这条旧日志不能证明相机从未回应，也不能直接归因为本地网络权限。

用户当前使用的入口为「网络 → 智能手机连接功能 → 连接」。核对一代 ZV-E10 官方指南后，客户端对接的素材传输入口应为：先按回放键显示照片，再进「MENU → 网络 → 发送到智能手机功能 → 发送到智能手机 → 这个影像」，或选择多个影像并确认，停在该入口生成的二维码界面。仍然对应 Imaging Edge Mobile，不涉及 Creators’ App。官方依据：[智能手机连接功能](https://helpguide.sony.net/ilc/2070/v1/zh-cn/contents/TP1000432927.html)、[发送到智能手机功能](https://helpguide.sony.net/ilc/2070/v1/zh-cn/contents/TP1000432932.html)（2026-10-31 查阅）。

同时补齐多网卡发现链路：Sony UDP 与 HTTP 均通过 `IP_BOUND_IF` 固定 Wi-Fi 接口，UDP 通过 `IP_MULTICAST_IF` 指定组播出口，不依赖有线网卡的默认路由。SSDP 无可用服务时，只对当前 Wi-Fi 链路内已知相机地址尝试 `:64321/DmsDescPush.xml`，不扫描其他地址。该固定描述路径来自 [ImagingEdge4Linux 的协议说明](https://github.com/schorschii/ImagingEdge4Linux#reverse-engineering)，仍是待 ZV-E10 实机核对的兼容路径；机型、同机控制/资源 URL 与禁止重定向规则全部保留。

标准日志新增发现开始、接收与过滤计数、描述地址来源（SSDP / 固定地址回退）、描述失败、机型拒绝与成功识别事件，不记录原始报文或素材内容。错误提示给出一代机型的准确菜单入口，区分描述读取失败与机型不匹配。回归通过真实 macOS 回环套接字检查接口与组播选项，并验证无组播回应/组播套接字失败时的 HTTP 回退、地址及机型边界、取消停止与诊断事件。

## Mini 5 Pro 连接诊断与修正（2026-10-26）

以下保留当天的诊断经过；协议和 HTTP 路径假设已由 [2026-10-27 成功抓包分析](mini5pro-capture-20261027.md) 修正，以新分析和当前代码为准。

实机网络检查：Mac 的有线网卡为 en0（192.168.5.47），无人机 Wi-Fi 为 en1（192.168.2.88），192.168.2.1 的实际路由是 en1；TCP 80 可达。UDP 9004 返回 connection refused，UDP 9003 返回有效的 9 字节握手。此次连接失败不能归因于同时连接有线网络。

已确认的原实现问题：Mini 5 Pro 误用了 Osmo 的 TCP 7001 唤醒、UDP 9004 和相机回放流程；蓝牙配对仍使用 `osmo` 而不是 `DJI FLY`；生成的安装身份未落盘；素材会话失败后保留蓝牙会话，仍每秒发送唤醒保活。用户报告调试期间无人机过热关机；未采集设备温度，不能据此认定单一原因。

修正行为：

- `internal/dji/aircraft.go` 独立实现 UDP 9003、动态 WLM 地址和会话应答；不用参考抓包中另一架无人机的固定地址。不发送飞行控制、相机录制、时钟写入或批量重放未知的初始化命令。
- `CameraWiFiDialer` 将 UDP（本地端口 9003）和 HTTP 都绑定到 CoreWLAN 识别的 Wi-Fi 网卡及其实际 IPv4 地址，macOS 通过 `IP_BOUND_IF` 固定接口；无需修改系统路由或关闭有线网络。
- 配对身份在请求授权前以 0600 权限原子保存，重启沿用；蓝牙使用 `DJI FLY`。会话建立成功、失败、取消和连接等待超时均有清理边界；快传建立最多 14 秒，没有响应的链路最多保留 8 秒。等待用户选择热点的蓝牙保活上限为 90 秒。
- 保留实际失败阶段：“未取得设备地址”“UDP 握手未完成”“Wi-Fi 已通但未确认快传会话”“目录格式未适配”。未知或截断目录不显示为空相册。
- 素材接收保留跨 UDP 包的 DUML 解析状态，去掉重复包，按 32 位分片序号合并并检查完整长度；成功、失败和取消都会释放目录传输槽。只有识别到真实路径才暴露素材；不把其他机型的 DCF 索引猜成 Mini 5 Pro 的文件名。
